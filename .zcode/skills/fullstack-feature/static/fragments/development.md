# 阶段三：增量开发与验证

## 执行前检查

1. 读取设计文档、全部 task、适用的 migration/Schema 文件、项目规范、构建清单和相邻实现。
2. 复核每项任务的依赖、状态、涉及文件、完整代码、启用 profile、风险和验证方式。
3. 不执行 `blocked` 任务；未完成依赖的任务保持 `pending`。
4. 高风险影响面仍无法可靠确认时，停止在设计/任务层，向用户报告缺口；不得用模板推断代码结构。

## 执行规则

按依赖拓扑和任务编号逐项执行：

1. 开始前将 task 标记为 `in_progress`。
2. 只修改任务中已确认或新增的文件。发现范围扩大时，更新设计、影响记录和相关任务后再继续。
3. 任务中的「完整代码」是实现基准：按其落盘写入，或交付给用户手动敲写；代码与实际文件冲突或执行中新探测到事实时，先回写更新任务的完整代码，再继续实现。
4. 遵循项目已探测的架构、命名、错误处理、认证、事务、迁移和依赖边界；不引入未经确认的新框架或模式。
5. 每完成一项能力，执行该任务的最小相关验证。
6. 实现、必需文档和验证成功后，才将 task 标记为 `completed`。
7. 缺少依赖、结构、文档、环境、权限或用户决策时，设为 `blocked` 并填写 `blocked_reason`。
8. `blocked` 任务按核心立场「blocked 解除协议」处理：用户补充决策或信息后，清空 `blocked_reason`、在任务中记录解除决策、状态回到 `pending`，重新校验依赖后再执行。

## 验证策略

从项目现有来源确定命令，优先级为：CI 配置 → 根目录脚本/Makefile/Taskfile → 包管理器配置 → 相邻模块文档与现有执行记录。

按适用 profile 执行：

| Profile | 示例验证（仅供映射，必须以项目实际命令替换） |
|---------|----------------------------------------------|
| Spring Boot / Maven | `mvn -pl <module> -am test` 或项目规定的 compile/install 命令 |
| Spring Boot / Gradle | `./gradlew test`、`./gradlew build` |
| Vue 前端 | `npm run lint`、`npm run typecheck`（TS 工程）、`npm run test`、`npm run build` |
| 数据库 | Flyway/Liquibase 迁移测试、测试数据库迁移、回滚或 schema diff |
| API/集成 | 契约测试、mock/fixture、集成测试、手动验证步骤 |

不得仅因示例命令存在而运行它；执行并报告实际探测到的命令。项目没有自动化验证时，记录手动验收步骤和其限制。

全栈功能：前后端各自验证通过后，执行联调验证——用项目实际的联调链路（Vue dev 代理（如 vite.config 的 server.proxy）、网关或同源部署）走通至少一条核心用户流，结果记入完成报告；纯手动联调时记录步骤与限制。

## 自动修复

仅自动修复范围明确的格式、类型、导入、拼写、已知 API 用法或测试夹具问题：

1. 记录失败命令与错误。
2. 结合项目规范和任务范围判断原因。
3. 修复后重跑最小相关验证；交付前重跑项目要求的完整验证。
4. 最多三轮；涉及需求语义、数据迁移安全、权限、契约兼容性或未知架构的问题，改为 `blocked` 并停止。

```text

|------|------|------|------|----------|
| 03_migration_add_record | migration | migrations/... | completed | 测试数据库迁移通过 |
| 05_api_create_record | api | src/... | blocked | 外部 API 契约待确认 |

验证：
- <实际命令或手动步骤> → 通过 / 失败 / 未执行（原因）
- <实际命令或手动步骤> → 通过 / 失败 / 未执行（原因）

阻塞项和风险：<无 / 详细说明>
```

只有所有计划任务均为 `completed`、必需验证完成且无未解决高风险项时，才能报告功能完成。
