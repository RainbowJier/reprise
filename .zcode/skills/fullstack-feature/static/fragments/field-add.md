# 特殊场景：已有字段或 Schema 变更

当用户要求向已有模型、表、文档 schema、配置结构或 API 类型增加/修改字段时使用。本流程不假定数据库方言、ORM（JPA/MyBatis 等）或迁移工具。

**路由**：用户明确要求加/改字段时直接进入；或在阶段一/二/三中探测到既有模型、schema 或契约字段变更时切入。先读取已有设计文档与 `tasks/` 目录，不修改历史任务；完成后新增增量任务并入阶段三按依赖执行，按本文件 Step 4 格式报告。确认时机见 manifest `special_flows.confirm_when`。

## 所需输入

| 参数 | 说明 |
|------|------|
| 变更内容 | 字段名、类型、可空性/默认值、语义、兼容性要求和业务规则 |
| 目标对象 | 模型、表、schema、配置或 API 类型及所属范围 |
| `$DOC_PATH` | 已有设计和任务目录；未知时先定位 |
| 影响范围 | 数据、接口、UI、索引、校验、集成、历史记录和发布方式 |

信息不足时先询问，不直接修改代码或 schema。

## Step 0：预检与变更任务

1. 读取项目规范、目标对象定义、相关 migration/schema、调用方、测试和已有功能文档。
2. 使用可用结构索引分析影响面；不可用时按核心立场记录降级限制。
3. 确认真实数据存储、方言和迁移工具；字段不涉及持久化时明确标记。
4. 检查字段或等价能力是否已经存在，避免重复变更。
5. 新建一个独立增量 task，例如 `{next}_migration_add_<field>.md` 或 `{next}_contract_add_<field>.md`，引用受影响的已完成任务；增量任务同样按任务模板包含「完整代码」章节；**不要修改已完成任务的状态、范围或验证历史**。
6. 缺少设计、迁移依据、数据兼容方案或高风险影响分析时，将新的增量任务标为 `blocked`，说明缺口并请求用户确认后再继续。

## Step 1：更新设计与影响记录

更新项目既有设计文档或 `$DOC_PATH/$FILE_SLUG.html`：

| 区域 | 需要更新的内容 |
|------|----------------|
| 范围与流程 | 字段如何改变用户流、状态、校验、权限或异步流程 |
| 影响范围 | 模型/schema、API、UI、集成、测试和发布影响 |
| 数据/Schema | 字段定义、关系、索引、迁移顺序、回填、回滚和兼容性 |
| 契约/UI | 所有请求、响应、事件、表单、展示和错误处理变化 |
| 验收 | migration、兼容、回归和发布验证步骤 |

## Step 2：生成或更新数据库变更

只有在已确认方言与数据变更策略后，才按项目实际落位方式生成变更（版本化 migration、启动初始化 SQL、功能目录自包含脚本或手工 DBA 脚本）。变更产物必须说明：

- 前置 schema 状态和目标状态（无版本化工具时记录基准脚本与日期）；
- 默认值、可空性、既有数据回填和线上兼容窗口；
- 索引/约束变化及性能影响；
- 执行主体、执行顺序、dry-run、测试数据库验证、回滚或恢复方案；
- 是否可重放，由项目数据变更策略约定决定。

未知方言、执行主体或回滚方式未确认时，保留设计和 `blocked` task，不生成猜测性的可执行 DDL。

## Step 3：更新关联实现

按项目实际依赖方向逐项更新：

| 区域 | 可能的变更 |
|------|------------|
| 模型/持久化 | 类型/实体、ORM/schema、查询、序列化、索引 |
| 契约/API | 请求、响应、事件 schema、校验、版本兼容 |
| 业务逻辑 | 默认值、状态机、权限、规则、回填/转换 |
| UI | 表单、显示、筛选、国际化和可访问性 |
| 集成 | 外部契约、消息 payload、映射、重试和幂等 |
| 测试/文档 | migration、回归、fixture、API/UI 文档和发布说明 |

仅把新增增量 task 转为 `in_progress`/`completed`；历史 task 不变。

## Step 4：验证与报告

按 `development.md` 中探测到的项目验证方式执行 migration、相关单元/集成/e2e、构建与兼容测试。通过后完成增量 task；失败或环境不足时标记 `blocked`。

```text
## Schema/字段变更结果

变更：<对象.字段 / schema path>
增量任务：<task ID>

| 类别 | 文件 | 状态 / 说明 |
|------|------|-------------|
| 设计 | <path> | 已更新影响与兼容策略 |
| Migration | <path / 不适用> | 已创建 / blocked（原因） |
| 实现 | <path> | 已完成 / 未涉及 |
| 测试 | <command or path> | 通过 / 失败 / 未执行 |

历史任务：未修改
阻塞项：<无 / 详细说明>
```
